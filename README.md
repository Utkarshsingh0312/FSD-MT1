# Event Registration Management REST API (SET A)

Full Stack Development Mid-Term Practical Assessment.

## Project Overview
This is a REST API built using **Node.js** and **Express.js** to manage college event registrations using an in-memory JavaScript array.

---

## Record Structure
| Field | Data Type | Description |
|---|---|---|
| `id` | Number | Unique identifier generated by the application |
| `participantName` | String | Full name of the registered participant |
| `eventName` | String | Name of the event |
| `department` | String | Participant's department |
| `ticketCount` | Number | Number of tickets booked (positive integer) |
| `paymentStatus` | String | Must be either `'Paid'` or `'Pending'` |

## API Endpoints

| Method | Endpoint | Description | Status Code |
|---|---|---|---|
| **GET** | `/api/registrations` | Fetch all registrations | `200 OK` |
| **GET** | `/api/registrations/filter?department=value` | Filter by department (case-insensitive) | `200 OK` |
| **GET** | `/api/registrations/pending` | Get all pending registrations | `200 OK` |
| **GET** | `/api/registrations/:id` | Get registration by ID | `200 OK` / `404 Not Found` |
| **POST** | `/api/registrations` | Create a new registration | `201 Created` / `400 Bad Request` |
| **PUT** | `/api/registrations/:id` | Update registration by ID | `200 OK` / `400 Bad Request` / `404 Not Found` |
| **DELETE** | `/api/registrations/:id` | Delete registration by ID | `200 OK` / `404 Not Found` |

> **Note on Route Ordering**: Specific endpoints (`/filter` and `/pending`) are mounted **before** the dynamic route (`/:id`) so that route strings are not incorrectly matched as IDs.

## Installation & Running

1. **Install Dependencies**:
   ```bash
   npm install
   ```

2. **Start Server**:
   ```bash
   npm start
   ```
   Server will run at `http://localhost:3000`.

3. **Run Automated Test Suite**:
   ```bash
   npm test
   ```
